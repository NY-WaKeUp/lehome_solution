# 租卡建议（对齐 Ilia 表现优先 · 含多卡比较）

日期：2026-11-11（检索时点；本版补充多卡）  
目标：**尽可能接近 Ilia 最终成功率**；在此约束下再比性价比。  
作者配方：`doc/2026-11-11-lehome_solution训练硬件与超参查证.md`（1×H200、全局 batch **192**、~**300k** steps、BC warm-up 论文 **20k**、rollout 多在 PRO 6000、异步飞轮）。

价格会变；下单以官网为准。AutoDL 公告 **2026-11-12** 可能调价。

---

## 结论先行（推荐排序）

在「对齐表现」下，**多卡可以、且应该纳入比较**——但多卡的价值几乎完全取决于：**能否稳住全局 batch≈192**，而不是卡时单价。

| 排序 | 套餐 | 对齐度 | 性价比（在 batch≈192 前提下） | 一句话 |
|------|------|--------|-------------------------------|--------|
| **①** | **1×H20 96GB**（冒烟过 batch=192）+ 另机 1×4090 做 rollout | 高（配方近、硬件非同型） | **通常最好**（~¥10/训时） | 租得到且 192 稳 → **首选落地** |
| **②** | **2×A800 80GB（同机 NVLink）** FSDP/DP 稳住全局 192 + 另机 4090 rollout | 中高 | 好（约 ¥12–17/训时量级） | 单卡 80G 冒烟挂、又不想付 H200 时 |
| **③** | **1×H200** + 另机 rollout | **最高**（同型） | 差于①若①可行（~¥35/训时） | 货源优先；预算够就锁 |
| — | **4×4090 / 2×4090** 强行主训 | **低**（多数情况稳不住全局 192） | 「元/时」看起来便宜，**(192·step)/元** 常很差 | 仅冒烟/工程验证；**不作对齐主路径**，除非实测证明全局 batch 能到 ~192（当前公开证据偏向不能） |

**硬规矩：** 全局 `batch_size` 对齐作者 ≈ **192**；OpenPI/JAX 里这是**全局** batch，且必须整除 `jax.device_count()`；每卡 micro-batch $= 192 / N$。  
把 192 砍到 16「为了多卡能跑」= **主动放弃对齐硬指标**，再便宜也不算本目标下的性价比优解。

## 1. 「对齐」硬指标

### 1.1 必须尽量满足

1. **全局 batch $B\approx 192$**（论文；含 5 flow samples / item、bf16 等配方）  
2. **总优化量级 ~300k steps** + 论文级 BC warm-up（**20k** 优先于 yaml 10k）  
3. **飞轮在**：BC → rollout → advantage 重算 → RL → …（Hub）；rollout/DAgger 规模不能「几乎为零」  
4. **数据混合不瞎改**（organizer BC / 自采 / DAgger 权重）

### 1.2 多卡时全局 batch 怎么拼

OpenPI：`batch_size` = **全局**；`batch_size % device_count == 0`；每卡数据份约为 $B/N$。  
`fsdp_devices`：默认 **1** = 主要 **数据并行**（所有可见 GPU 已参与）；增大 = 增加 **模型分片**（单卡装不下整模时才刚需）。见 [train.py](https://github.com/Physical-Intelligence/openpi/blob/c23745b5/scripts/train.py)、[issue #327](https://github.com/Physical-Intelligence/openpi/issues/327)、[issue #600](https://github.com/Physical-Intelligence/openpi/issues/600)。

| 拼法 | 公式 | 与作者接近？ | 表现风险 |
|------|------|--------------|----------|
| **A. 弱缩放对齐（推荐）** | 全局 $B=192$ 固定；$N$ 卡；每卡 $b=192/N$；仅在显存不够时加 FSDP | **接近**：每步梯度统计量与作者同 batch 量级 | 通信与数值路径仍可能略异于单卡，但优于改 $B$ |
| **B. 强缩放「假对齐」** | 固定很小每卡 $b$，增加 $N$ 却**不**把全局拉回 192 | **不接近** | 梯度噪声大；MFU 常差（gather 盖不住小 matmul）[Sharder](https://virkvarjun.github.io/OpenPI-GPU/) |
| **C. 为凑速度抬全局 batch≫192** | 例如 8 卡把 $B$ 提到 512 | 偏离作者 LR/噪声设定 | 需重调 LR；非「复现」 |
| **D. 社区 4×4090 类** | 全局 $B\sim 4$，$b=1$，重 FSDP、关 EMA | **远离** | 能通管线；**成功率对齐预期应显著下调** |

**接近作者的多卡定义：**  
$\text{config.batch_size}=192$，且 $N\mid 192$（如 $N\in\{2,3,4,6,8\}$），每卡 $b=192/N$，优先 `fsdp_devices=1`；仅当激活/优化器装不下再增大 `fsdp_devices`。

## 2. 候选比较（价格公开检索 · 吞吐需自测）

定义（在 **$B=192$ 已跑通** 时才有意义）：

\[
\eta = \frac{B \times (\text{steps/s})}{P_{\text{元/时}}}
\]

若某方案 **稳不住 $B\approx 192$**，表中标「对齐硬指标：否」，$\eta$ 不与对齐方案直接比价。

## 3. 多卡 JAX / OpenPI / FSDP：何时值、何时不值

| 维度 | 要点 |
|------|------|
| **通信** | FSDP 每层 all-gather / reduce-scatter；小 micro-batch 时通信占比飙升，卡加了 step/s 几乎不动 [Sharder](https://virkvarjun.github.io/OpenPI-GPU/) · [issue #600](https://github.com/Physical-Intelligence/openpi/issues/600)（也有 I/O 瓶颈） |
| **显存** | FSDP 切参数与优化器，**激活仍大致随每卡 batch**；4090 的瓶颈常是激活而非「总显存相加」 |
| **工程** | 同机多卡（AutoDL 同实例）简单；多机要联系客服；NVLink vs PCIe 差一截；调试 OOM/数值更难 |
| **与作者单卡差** | 即使用 $B=192$，collective 顺序与单卡非 bit-identical；可接受为「配方对齐、轨迹近似」 |

**多卡更值：**  
- 单卡（H20/A800）**装不下** $B=192$，而 **2×A800（或同档双卡）冒烟能装下**；  
- 同机 NVLink；测得 $\eta$ 明显高于 1×H200；  
- 飞轮与 rollout 仍独立加机器（多卡训练机 ≠ 替代采集）。

**多卡不值：**  
- 只能把全局 batch 压到 ≪192 才能跑；  
- 4×4090 通信+工程换来的是「能训」而不是「对齐」；  
- step/s 相对 1 卡提升 < 20%，但费用 ×2～4（弱缩放失败）。

## 4. 三个可执行套餐

### 套餐 S1 — 落地首选（对齐 × 性价比）

- **训：** 1× **H20 96GB**（或实测等价的 PRO 6000 96GB）  
- **采：** 1× **4090**（Isaac / rollout）  
- **价：** 训 ~¥10/时 + 采 ~¥2/时 ≈ **¥12/时** 量级（按量）；长跑 **包周**  
- **对齐度：** 高（$B=192$ 为前提）  
- **风险：** H20≠H200 算力；11-12 调价；192 冒烟失败则改 S2/S3  
- **动作：** 先 30–60 min 冒烟 → 过则包周锁训卡

### 套餐 S2 — 多卡性价比（单卡 80G 不够时）

- **训：** **2×A800 80GB** 同机；`batch_size=192`（$b=96$）；先 `fsdp_devices=1`，OOM 再加 FSDP  
- **采：** 1×4090  
- **价：** 训约 **¥12–17/时** 量级 + 采 ~¥2  
- **对齐度：** 中高（全局 192 + 飞轮；非单卡轨迹）  
- **风险：** 双卡库存、NVLink 有无、通信拖 step/s；工程量高于 S1  
- **何时上：** S1 冒烟失败或 H20 无货，且 1×A800 也挂

### 套餐 S3 — 最大对齐（预算优先保同型）

- **训：** **1×H200** @ ~¥35/时（货少）  
- **采：** 1×4090 或 PRO 6000  
- **对齐度：** **最高**  
- **风险：** 单价高、难抢；总账随 step/s 波动大  
- **何时上：** 追求与论文硬件一致；或 S1/S2 均无法稳住 192

### 不单独成「对齐套餐」：N×4090 主训

- 仅当你 **实测** 全局 $B\ge 128\text{–}192$ 可稳定（当前公开/社区信息偏向 **不能**）才晋级比较 $\eta$。  
- 否则：只用于代码/数据管线冒烟，然后迁到 S1/S2/S3。

## 5. 预算框架（多卡同样适用）

\[
T \approx \frac{N_{\text{steps}}}{\text{steps/s}\times 3600},\quad
C_{\text{训}}=T\times P_{\text{整机（多卡合计）}},\quad
C_{\text{总}}=C_{\text{训}}+C_{\text{rollout}}+C_{\text{盘}}
\]

比较时用 $\eta$（见上），**禁止**用「单卡单价 × 卡数」而不测 step/s。  
300k steps 墙钟：**测出来再乘**；不要用未验证的 step/s 报假精确总价。

**对齐下仍可省：** 冒烟→包周；训采分离；无卡模式传数；镜像复用；付费盘用完缩容；长跑不用抢占/闲时。

## 6. 客观边界（不变）

硬件 + batch=192 仍不足以保证与 Ilia 同成功率：随机性、rollout/DAgger 规模与质量、数据混合、评测协议、论文/yaml 差异。多卡还会多一层非 bit-identical。

## 7. 租前核对（多卡版）

1. 写死目标：全局 **batch=192**、~300k、20k warmup、飞轮开。  
2. 按序试冒烟：**H20 → 1×A800 → 2×A800 → H200**；4090 多卡只作对照实验。  
3. 记录：峰值显存、$b=192/N$、step/s、$P$、$\eta$。  
4. 多卡确认同机 +（尽量）NVLink；`batch % N == 0`。  
5. 先 `fsdp_devices=1`，不够再加。  
6. 另开 rollout 机；训机不兼满载 sim。  
7. 过冒烟再包周；盯 11-12 调价。  
8. 差异表：卡数/FSDP/$B$/数据源 —— 方便解释成功率差。

## 8. 1×A800 + 梯度累积？效果与速度（查证补充）

**结论先行：** 可以用累积把有效 batch 凑到 ≈192，但**不是免费午餐**——对效果是「多数情况下近似、个别路径不等价」；对墙钟**几乎不可能**追上「显存装得下的真 batch=192」。OpenPI / lehome **原生不支持** grad accum，要改训练循环。

### 8.1 是什么 / 边界

梯度累积：连续做 $K$ 次 micro-batch 的 fwd+bwd，把梯度求和/平均后**一次** `optimizer.update`，使有效 batch $B_{\text{eff}}\approx K\cdot b$。它解决的是「单次装不下 $B$」；**不**解决算力不够、**不**让小卡和真大 batch 同速。见 [ZeroEntropy 概念页](https://zeroentropy.dev/concepts/gradient-accumulation/)、[Quant Memo](https://quantmemo.com/concepts/gradient-accumulation-and-effective-batch-size)。

### 8.2 对训练效果

| 情形 | 与真 $B=192$ |
|------|----------------|
| 损失对样本线性可加、loss 正确按总样本平均、同有效 batch、同 LR、Adam 类 | **近等价**（SGD 精确；Adam 仅有限精度/归约顺序差）置信度 **高** |
| BatchNorm（按 micro-batch 统计） | **不等价**；本项目主干为 **RMSNorm / AdaRMS**（非 BN），BN 陷阱**基本不适用** 置信度 **高** [openpi gemma RMSNorm](https://github.com/Physical-Intelligence/openpi/blob/main/src/openpi/models/gemma.py) |
| Dropout / flow 噪声 / `train=True` 随机性 | 微差（噪声实现路径不同）置信度 **中** |
| loss 归一化写错（忘除 $K$） | 等效 LR ×$K$，危险 |
| **经典「AWR 在 micro-batch 内 softmax/归一化权重」** | **对本仓库基本不适用**：作者把 AWR 做在**采样器**上 $P(i)\propto e^{\mathrm{clip}(A,-2,2)}$，action loss 是 **unweighted batch mean**，不是 batch 内 `normalized_exp_advantage_weights` [arXiv §2.3](https://arxiv.org/html/2606.27163v3) · [data_loader priorities](https://github.com/IliaLarchenko/lehome_solution) |
| **aux**：`type_balanced_weighted_mean`（按 batch 内出现的 garment type 再平均） | micro-batch 更小时「某 type 缺席」更频繁 → aux 梯度与真 192 **有可见统计差**；action 主损失影响较小。定性：主任务偏差 **小到中**；aux **中**。置信度 **中** |
| EMA | 必须**每个有效 step 更新一次**；若误调 $K$ 次 `train_step` 会多更 EMA |

OpenPI / lehome 训练步：一次 `value_and_grad` → 一次 `tx.update`（+可选 EMA）；**无** `grad_accum` 配置项。[openpi train.py](https://github.com/Physical-Intelligence/openpi/blob/c23745b5/scripts/train.py) · lehome `scripts/train.py`。

### 8.3 对训练速度

墙钟直觉（同卡、目标有效 batch 固定）：

\[
T_{\text{opt-step}}^{\text{accum}} \approx K\cdot T_{\text{fwd+bwd}}(b) + T_{\text{optim}}
\quad\text{vs}\quad
T_{\text{opt-step}}^{\text{true}} \approx T_{\text{fwd+bwd}}(Kb) + T_{\text{optim}}
\]

- 只省了 $K-1$ 次 optimizer step；**不算力减半**。  
- 小 $b$ 常更吃显存带宽、MFU 更低 → 往往 **比「同总样本一次算完」更慢**，不是持平。[throughput 文](https://mbrenndoerfer.com/writing/gradient-accumulation-memory-effective-batch-size-training/throughput-and-wall-clock-time) · [PastAGI T4/L4](https://pastagi.com/engineering/gradient-accumulation-t4-l4-throughput/)。  
- 相对「更大显存卡真跑 192」：1×A800+accum 墙钟通常 **明显更差**。

### 8.4 对 1×A800 的建议

1. **冒烟真 $b=192$ 通 → 别用 accum。**  
2. 只能 $b\in\{48,64,96\}$ → accum 到 192 是**效果折中 + 速度更慢**的备选（需改 train loop、正确平均梯度、EMA 只更一次）。  
3. **性价比：** **2×A800 真并行全局 192**（每卡 $b=96$）通常优于 **1×A800+$K$ 累积**——并行吃吞吐，累积只换显存、墙钟近线性变差。若 1×A800 能真 192，则优于 2×A800+通信。  
4. 仍先冒烟峰值显存；没有实测不要假设 A800 装得下/装不下 192。

**置信度总评：** 速度结论 **高**；本项目 action/AWR 路径对 accum **比「loss 内 AWR 归一化」友好** **高**；aux/随机性导致的最终成功率差距 **中（未实测）**。

## 10. 用户拟租：A100 · 20核 · 内存84G · 系统盘200G+数据盘200G · 两天

### 结论

**可以租，但定位只能是「冒烟 / 测能否 batch=192」，不是「两天对齐 Ilia」。**

前提核对：

1. **必须确认是 A100 80GB 显存，不是 40GB。** 你写的「内存 84G」在租卡页通常是 **主机 RAM**，不是显存。40GB 几乎肯定装不下作者配方。
2. **两天预算**：环境 + 数据 + 冒烟 + 记 step/s 与峰值显存；**不够**跑 20k warmup + 300k。
3. **盘 200+200≈400G**：低于作者 README「500+ GB」建议；只做 train_only 冒烟往往够，全量 Isaac/多 ckpt 会紧。
4. **主机内存 84G**：比常见 A100 挂 128G RAM 紧；数据 loader 顶满可能被 kill（AutoDL 超内存硬杀）。监控主机内存。

## 13. 「2.4B 用不了 141G」——对，但别混两件事

**权重很小，大的是大 batch 激活。**

粗账（与 Aserver 实测一致）：
- 总参 ~2.83B → 权重体积约 **10.6 GiB**（混合精度）
- 可训 ~2.42B → Adam 一阶/二阶约 **~18 GiB** 量级
- 静态：参数+moments ≈ **~29 GiB** 量级（还没算大 batch 激活）

作者用 H200 的核心是 **batch=192 + 5 flow samples**，激活随 batch 近似线性涨；双 4090 上 **b=16** 时运行态约 **15 GiB/卡** 已通，推到 192 约 **×12** 量级的激活压力（非精确外推）。  
所以：**不需要 141G「装模型」**；141G 是「大 batch 配方的显存天花板」。峰值可能落在 40–100G 某档——**公开未知**，要用 80G/96G 冒烟，而不是默认必须 H200。
